# NetInfect – evaluation report

Generated by `src/ml_pipeline/train_ids.py`. Unit: one Zeek connection, features over a 2s sliding window per source IP.

## Dataset

- Benign connections: 1857 · attack connections: 1321
- Attack types: http_flood (1111), slowloris (80), ssh_bruteforce (54), portscan (48), web_attack (24), exfiltration (4)
- Temporal split: 1779 train rows, 1399 test rows (13 minutes of benign test traffic)

## Trivial baseline: `conn_count >= 3` in the window, no ML

F1 0.9879, recall 0.9761, precision 1.0. When a one-line rule scores almost as well as the model, the dataset is too easy to judge the model: the simulated benign users open at most 2 connections every 2 seconds, while almost every attack is a burst.

## Random split (for comparison only)

F1 0.9987, recall 0.9975, precision 1.0. A random split puts neighbouring windows of the same attack in both train and test, so it overstates performance.

## Caveats

- Both benign and attack traffic are synthetic and generated by this project's scripts; results describe this lab, not a real network.
- The attack capture contains three runs of the same attack script, so the test set is small and very similar to the training set.
- web_attack is an L7 attack: at the connection level it looks like normal browsing. It is caught here mostly because the same source IP was scanning and brute-forcing in the same 2-second window; on its own it is the WAF's job.
- The Isolation Forest alone flags a large share of benign traffic; the Random Forest is what makes the alerts precise.
